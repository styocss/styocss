#118 (fix/118-host-project-root) added `EngineHostContext`/`context.host` in core (diagnostics.ts, plugin.ts), threaded `host.projectRoot` through `packages/integration/src/ctx.ts` and `packages/plugin-design-tokens/src/load.ts`, and added `packages/plugin-design-tokens/src/host-root.test.ts` (7 tests) plus new describe blocks in `packages/core/src/plugin.test.ts` and `packages/integration/src/ctx.test.ts`. Reviewed clean — no blocking findings, all 10 issue-listed regression scenarios mapped to a test (Vite-root/Nuxt/monorepo covered abstractly via generic "host projectRoot ≠ shell cwd" temp-dir tests, since unplugin/nuxt only reach core through `createCtx`'s `cwd` signal — verified no direct `createEngine` calls in unplugin/nuxt src).

Non-blocking findings (all reported to owner, none required a change):
1. `host-root.test.ts`'s standalone-fallback test uses real `process.chdir()` (process-wide). Verified vitest 4.1.9's default pool is `"forks"` (`resolved.pool ??= "forks"` in `node_modules/.pnpm/vitest@4.1.9*/dist/chunks/coverage.*.js`), so forks isolate the mutation per OS process and tests in this file run sequentially (no `.concurrent`) — safe today, but this is the one test in the file that mutates global state, and the *same* fallback branch could be exercised without chdir by importing the base `designTokens()` from `./index` with an injected `runtime.cwd` (the factory already supports this — see `types.ts` `LoaderCtx`/`DesignTokensRuntimeOptions.cwd`, used by `node.ts`). Would silently become a cross-file race if `pool: 'threads'` were ever adopted (worker_threads share one process, so `process.chdir` is truly global across them, unlike forks).
2. The "absolute designTokens.root authoritative" test does NOT discriminate the fix — verified by direct execution that old root logic (`config.root ?? runtime.cwd?.() ?? '.'`) and new logic (`isAbsolute(config.root) ? resolve(config.root) : ...`) produce an identical result for an absolute `config.root`. It only fails pre-fix because `context.host` didn't exist at all (crash), not because it exercises the split-root bug. The sibling "relative designTokens.root" test DOES discriminate the bug (confirmed: old code would resolve the relative root against the real shell cwd via downstream `resolve(root, source)`, new code resolves against `projectRoot`).
3. `host-root.test.ts`'s neutral-entry test reads `index.ts` via `__dirname` (works — Vite/Vitest SSR shim — verified 7/7 green) but every other test in the same package uses `fileURLToPath(new URL('./x', import.meta.url))` (repo is `"type": "module"` throughout, no other `__dirname` usage anywhere in `packages/`). Minor consistency/portability nit, not a failure.
4. The neutral-entry `source.includes('node:')` check only scans `index.ts` text, not transitively `./load` (which `index.ts` imports). Currently harmless since `load.ts` also has zero `node:` imports today (uses `pathe` + injected `runtime.readFile`), but the test wouldn't catch a future `node:` import added to `load.ts`.

Verification method worth reusing: confirmed upstream `dist/` (core, integration, plugin-design-tokens) was actually rebuilt with the #118 changes by content-grepping compiled output for `projectRoot` (not just relying on mtime, which was ambiguous/coincidental) before trusting the green downstream suite runs (core 148/148, plugin-design-tokens 168/168 @ 95.74% branch, integration 330/330, plugin-fonts/icons/reset/typography all green, typecheck clean on core/integration/plugin-design-tokens).

**Why:** keeps the fail-without-fix bar and the pool/chdir hazard visible for whoever reviews the next host-context-adjacent issue (#121, #122 per [[pikacss-110-harness-state]]), and documents that "does this test discriminate the bug" requires actually running old vs new logic, not just checking it fails pre-#118 for unrelated plumbing reasons.
**How to apply:** for future design-tokens/root-resolution changes, re-check whether a new test's failure pre-fix is caused by the specific logic branch under test or by unrelated scaffolding (host plumbing, new required context fields) crashing first.
